# Проверка решения на размеченных данных

Оценочный стенд обогащения (категория / важность / тип документа) — без изменений в конвейере.

- датасет: `backend/data/eval/enrichment.json` — 52 размеченные записи (ИТ + госрегулирование),
  4 категории, 3 уровня важности, npa/news;
- харнесс: `backend/app/eval/enrichment.py` — гоняет датасет через `provider.make_news(...)`

- тест: `backend/tests/test_eval_enrichment.py` — на `mock` (детерминирован, в CI);
- прогон на реальном LLM:
  `docker compose exec -e LLM_PROVIDER=openai_compat backend python -m app.eval.enrichment`

### Сравнение моделей (профиль + рубрика, тот же датасет)

| Модель | category | importance | doc_type | coverage | комментарий |
|---|---|---|---|---|---|
| `deepseek/deepseek-v4-flash` (прод) | ~0.90 | ~0.78 | ~1.00 | 1.00 | склонна занижать MEDIUM→LOW |
| `openai/gpt-5.1` | 0.92 | 0.69 | 1.00 | 1.00 | наоборот, завышает: 11/19 LOW→MEDIUM |
| `anthropic/claude-sonnet-5` | 0.65 / 0.81 | 0.67 / 0.85 | 0.73 / 1.00 | 0.77 / 1.00 | лучшая importance, но группирует агрессивно (в одном прогоне 23% записей выпали из групп → coverage 0.77) и путает репутацию с трендами |

**Вывод.** «Более крутая модель» тут не выигрывает однозначно: gpt-5.1 хуже по важности,
claude-sonnet-5 нестабилен по группировке и слабее по категории. Узкое место (importance,
репутация↔тренды) — это субъективность разметки и промпт, а не потолок модели. Прод-модель
`deepseek-v4-flash` конкурентоспособна и дешевле — менять смысла нет.

### Что дало улучшение importance ~0.63 → ~0.78

Раньше в `_NEWS_SYS` было определено только `high`, `medium`/`low` модель угадывала; плюс
важность считалась «в вакууме», без понимания, чей это бизнес. Сделано (заход 4, **в проде**):
- `Project.profile` (proto + миграция `d4a9f1e2b8c6` + `UPDATABLE`) — свободный текст о бизнесе;
- `LLMProvider.make_news(topic, messages, profile="")`; `handle_compose` передаёт `project.profile`;
- в `_NEWS_SYS` — блок профиля (когда задан) и полная рубрика high / medium / low с привязкой
  к влиянию на бизнес;
- в eval-датасете — `business`-профиль + переразметка всех меток `importance` относительно него.

Систематическое занижение MEDIUM → LOW упало с ~10–11 промахов до ~5; катастрофических
HIGH → LOW больше нет. Профиль пуст → промпт без блока профиля, поведение как до захода 4.

### Confusion (реальный LLM, + профиль + рубрика, прогон 1), строки — метка, столбцы — предсказание

```
category      COMPET REGUL REPUT TREND     importance   HIGH  LOW  MED     doc_type  NEWS  NPA
COMPETITORS     10     0     0     2       HIGH           9    0    3       NEWS       40    0
REGULATORY       0    16     0     0       LOW            0   16    3       NPA         0   12
REPUTATION       0     2    10     0       MEDIUM         0    5   16
TRENDS           0     0     0    12
```

**Выводы.**
- `doc_type` — идеально (12/12 НПА, 40/40 новостей). Маркеры «закон / приказ / постановление /
  указ» надёжны.
- `category` 0.92 — regulatory 16/16, trends 12/12. Остаток ошибки: «репутация → регуляторика»
  (проверки ФАС/антимонопольки, 2 шт) и «конкуренты → тренды» (2 шт).
- `importance` 0.79 — заметно лучше. Остаток: HIGH → MEDIUM (3) и шум MEDIUM ↔ LOW (по 3–5) —
  это субъективная граница «косвенное vs фон», не системная ошибка.
