# Метрики обогащения — оценка на размеченных данных

Стенд: `backend/app/eval/enrichment.py` (+ тест `backend/tests/test_eval_enrichment.py`).
Прогоняет датасет через тот же `make_news`, что и воркер, считает accuracy по трём измерениям.

## Данные

`backend/data/eval/enrichment.json` — **52 новости, размеченные вручную** (тема: ИТ + госрегулирование).

| Поле | Значения | Как размечено |
|---|---|---|
| `category` | регуляторика / репутация / конкуренты / тренды | по сути новости (объективно) |
| `doc_type` | НПА / новость | по сути новости (объективно) |
| `importance` | high / medium / low | **относительно профиля бизнеса-заказчика** (в файле `business` — вендор корпоративного ПО и облачных сервисов) |

Распределение importance: high 12 · medium 21 · low 19.

```json
{ "id": "e02",
  "text": "Правительство утвердило постановление о переходе госкомпаний на преимущественно российское ПО к 2026 году...",
  "category": "регуляторика", "importance": "high", "doc_type": "npa" }
```

**Ограничение:** метки importance — субъективная разметка **одного человека**, без второго
аннотатора и доменного эксперта. Читать как «согласие с заданной бизнес-рамкой», не как истину.
Абсолютные числа — ориентир; ценно **сравнение конфигураций** на одних и тех же метках.

## Конфигурации (что менялось в системном промпте `_NEWS_SYS`)

| | рубрика importance в промпте | профиль бизнеса в промпте |
|---|---|---|
| **A** | определён только `high` (одна строка) | нет |
| **B** | полная рубрика `high` / `medium` / `low` с критериями | нет |
| **C** (прод) | полная рубрика | **да** — `Project.profile` подставляется, «важность оценивай по влиянию на этот бизнес» |
| **D** | определён только `high` | **да** |

Всё остальное (группировка, батчинг, схема ответа, датасет, метки) идентично.
`accuracy` = доля верных из 52, по каждому измерению отдельно.

## Метрики (deepseek-v4-flash, RouterAI; 2 прогона на конфиг, разброс ±3–5 п.п.)

| Конфиг | category | importance | doc_type |
|---|---|---|---|
| **A** старый промпт, без профиля | 0.92 / 0.94 → **~0.93** | 0.44 / 0.54 → **~0.49** | 1.00 |
| **B** рубрика, без профиля | 0.92 / 0.90 → **~0.91** | 0.58 / 0.56 → **~0.57** | 1.00 |
| **D** без рубрики, + профиль | 0.88 / 0.90 → **~0.89** | 0.67 / 0.69 → **~0.68** | 1.00 |
| **C** рубрика + профиль (прод) | 0.83 / 0.87 → **~0.85** | 0.75 / 0.73 → **~0.74** | 1.00 |

Тот же конфиг **C** на **claude-sonnet-5**: category **~0.86**, importance **~0.81**, doc_type ~0.99.

### Confusion importance

старый промпт, без профиля (acc 0.48):
```
метка \ пред   HIGH  MED  LOW
HIGH             5    6    1     ← из 12 угаданы 5
MEDIUM           6    9    6
LOW              2    6   11
```

C = рубрика + профиль, claude-sonnet-5 (acc 0.81):
```
метка \ пред   HIGH  MED  LOW
HIGH            11    1    0     ← из 12 угаданы 11
MEDIUM           2   14    5
LOW              0    2   17
```

## Выводы

**importance** (главная слабая метрика): 0.49 → 0.74 (+0.25).
- вклад **профиля**: A→D **+0.19** (0.49 → 0.68) — основной рычаг, знание «чей это бизнес»;
- вклад **рубрики** поверх профиля: D→C **+0.06** (0.68 → 0.74).
- потолок ~0.81 даже у claude-sonnet-5 → остаток (MEDIUM ↔ LOW) — в основном неоднозначность
  самих меток на границе «косвенное влияние vs фон», не ошибка модели.

**category**: профиль и рубрика её слегка топят (~0.93 → ~0.85). Причина — слова-триггеры в
тексте профиля («конкуренты на рынке облаков», «импортозамещение», «утечки») и рубрике
(«НПА», «штрафов/проверок/суда»). Эффект небольшой, стабильный в обоих прогонах.
- **компромисс D** (профиль без рубрики): category ~0.89, importance ~0.68 — если важна
  категоризация, D балансирует лучше, чем прод-C.

**doc_type**: ~1.00 во всех конфигах — маркеры «закон / приказ / постановление / указ» надёжны,
промпт важности на него не влияет.

## Воспроизвести

```bash
# прод-конфиг (C), текущий промпт:
docker compose exec -e LLM_PROVIDER=openai_compat backend python -m app.eval.enrichment

# на другой модели:
docker compose exec -e LLM_PROVIDER=openai_compat -e LLM_MODEL=anthropic/claude-sonnet-5 \
  backend python -m app.eval.enrichment
```

Сравнение конфигураций A/B/C/D — скриптами в истории разработки (патчат `_NEWS_SYS` +
вызывают `app.eval.enrichment.run` с `profile=""` / `profile=<текст>`).

## Для слайда

**Что мерили.** 52 новости, размеченные вручную по 3 измерениям (категория / важность /
тип документа). Прогон через тот же LLM-конвейер, что в проде. Метрика — accuracy.

**Что улучшали.** Оценку **важности** новости — она относительна: одно и то же событие
критично для одного бизнеса и фон для другого. В промпт добавили **профиль
бизнеса-заказчика** и **рубрику** high / medium / low с критериями.

**Результат** (deepseek-v4-flash → в скобках claude-sonnet-5):

| | было | стало |
|---|---|---|
| важность | 0.49 | **0.74** (0.81) |
| категория | 0.93 | 0.85 (0.86) |
| тип документа | 1.00 | 1.00 |

- прирост важности **+0.25**: профиль бизнеса даёт +0.19, рубрика — ещё +0.06;
- лёгкая просадка категории (−0.08) — слова из профиля смещают классификацию, эффект
  небольшой и стабильный;
- тип документа (НПА / новость) распознаётся идеально в любой конфигурации.

**Честно про данные.** Метки важности — разметка одного человека, без второго аннотатора.
Абсолютные числа — ориентир; надёжен **сам факт улучшения** на фиксированной разметке.
Потолок ~0.81 даже у сильной модели → часть остатка — неоднозначность границы
«косвенное влияние vs фон», а не ошибка модели.
